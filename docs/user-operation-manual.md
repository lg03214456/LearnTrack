# LearnTrack 使用者操作手冊與流程評估

## 1. 使用者先了解的核心概念

LearnTrack 的資料關係是：

```text
教材範本 → 班級 → 排課
               └→ Enrollment ← 學生
                         ↓
                 點名／進度／成績
                         ↓
                 學生個人頁／分析
```

- 教材範本是可重複套用的教學內容，不是學生個別進度。
- 班級負責教師、科目、年級、容量與固定排課。
- 學生和班級透過 Enrollment 關聯，因此一位學生可以同時加入多個班級。
- 點名依「日期 + 班級排課 + active Enrollment」產生應到名單。
- 成績、出勤及學習進度最後應集中回學生個人頁供追蹤。

## 2. 建議的完整操作順序

左側「教學功能」以日常查詢順序排列，「學生名單」是第一個入口；點擊左上角「補教紀錄／PROGRESS HUB」Logo 也會返回 `/students`。因此不論目前位於班級、教材、點名或個人頁，都能快速回到學生主頁重新搜尋或篩選學生。

### A. 第一次建立系統／新學期

1. 到「帳號管理」建立教職員帳號。
2. 到「角色權限」確認負責人、管理員、教師與助教的操作範圍。
3. 到「教材範本庫」建立年級、科目與版本內容。
4. 到「課程班級」新增班級，設定教師、容量與狀態。
5. 在班級編輯頁加入學生並設定每週上課時段。
6. 從班級卡片點「查看名單」，確認 `/students?classId=<id>` 顯示正確學生。
7. 到「出缺席」選擇有排課的日期，確認系統能帶出應到名單。

這段流程整體合理，而且資料建立順序符合依賴關係。需要改善的是班級建立頁目前同時包含太多內容；大量學生與多筆時段時，建議改為「基本資料 → 排課 → 加入學生 → 確認」四區段或步驟式編輯。

### B. 老師每日操作

目前可行流程：

1. 進入「出缺席」。
2. 選擇日期與班級，修改缺席、遲到或請假學生。
3. 進入「學生進度」查看整體狀態。
4. 從「學生名單」進入學生個人頁。
5. 在個人頁登錄或更正小考成績、查看教材進度。
6. 進入「學習指標」檢視班級與全校趨勢。

目前最大的問題是第 2～5 步分散在不同頁面。老師點名後通常會立刻登錄「今天做到哪裡、考了哪張卷、幾分、需要注意什麼」，不應先離開班級情境，再到總名單搜尋同一位學生。

建議目標流程：

```text
今日工作台
  → 選擇日期／時段／班級
  → 系統帶出應到學生
  → 批次點名
  → 同列登錄今日教材、進度、考卷、成績、評語
  → 標記需要追蹤的學生
  → 完成今日紀錄
```

### C. 查詢學生個人狀況

1. 進入「學生名單」。
2. 使用姓名／學號搜尋，或由班級卡片進入已篩選名單。
3. 點學生姓名進入個人頁。
4. 查看基本資料、所屬班級、修課計畫、進度與考試歷史。
5. 有權限者可編輯資料或登錄／更正成績。
6. 返回時應保留原本的 `classId`、搜尋、狀態與頁碼情境。

目前 1～5 步的概念合理；第 6 步是重要改善點。若返回後失去班級篩選，老師需要重新找學生，會造成高頻操作摩擦。

### D. 班級異動與結業

1. 到「課程班級」搜尋目標班級。
2. 點「編輯」調整教師、容量、學生或排課。
3. 學生退班時結束 active Enrollment，不刪除歷史成績與出勤。
4. 學期結束先設為「已結業」。
5. 確定不再日常使用後再「封存」。

這個流程合理。結業與封存應持續使用明確確認視窗，且在畫面上說明「資料會保留、不再產生未來點名名單」。

### E. 學生停課、封存與恢復

1. 暫時不上課但可能回班時，將學生設為「停課」，不要封存。
2. 確認不再日常使用時，在學生名單點「封存學生」並填寫原因。
3. 系統將學生從一般名單、未來點名與進度監控隱藏，並結束現行 Enrollment；歷史資料完整保留。
4. 需要查閱時，以狀態篩選選擇「已封存」。
5. 恢復後先回到「停課」，由管理者重新確認班級，再視情況改為在籍。

班級結業與學生封存是兩個獨立生命週期；班級結業不會自動封存學生。

## 3. 身分切換與正式權限

左側選單底部的「Mock 身分與操作導引」可切換 Owner、主任、老師、學生與家長。選單會在切換前顯示資料範圍，切換後自動前往該身分的建議入口；下方同時列出主要操作。這只是開發驗證工具，不等同正式登入，正式版仍須由 Supabase Auth、membership 與 RLS 判斷身分。

| 身分  | 資料範圍   | 建議入口          | 可以操作                                   | 明確禁止                                   |
| ----- | ---------- | ----------------- | ------------------------------------------ | ------------------------------------------ |
| Owner | 全機構     | `/classes`        | 全部教務、班級生命週期、帳號與角色治理     | 不可停用或降級最後一位 Owner               |
| 主任  | 全機構     | `/attendance`     | 學生、班級、教材、點名、分析與一般帳號管理 | 不可管理 Owner、不可修改系統角色與角色權限 |
| 老師  | 指派班級   | `/attendance`     | 指派班級點名、學生進度、個資與成績紀錄     | 不可新增／封存班級、換老師、管理帳號或角色 |
| 學生  | 僅本人     | `/students/stu-1` | 唯讀查看本人進度、出缺席、考試與修課計畫   | 不可查看其他學生或任何管理頁，不可寫入     |
| 家長  | 已綁定孩子 | `/students/stu-1` | 唯讀查看孩子進度、出缺席、考試與修課計畫   | 不可查看未綁定學生、內部管理資料或寫入     |

直接輸入 URL 不會繞過權限：Page、Repository、Service 都會以 server 解析的 Actor 再驗證；無權頁面顯示拒絕存取，無權資料查詢採 fail-closed。

### 快速驗證流程

1. 切換 Owner，確認可見帳號管理及角色權限，並可管理全機構班級。
2. 切換主任，確認可管理日常教務，但角色權限為唯讀、Owner 列不可操作。
3. 切換老師，確認僅出現 `cls-1` 指派範圍且班級設定、生命週期與帳號功能不可操作。
4. 切換學生，確認直接進入 `stu-1` 個人頁，進度與出缺席只顯示本人。
5. 切換家長，確認只可查看 `stu-1`，手動開啟其他學生 URL 應被拒絕。

## 4. 各角色的合理入口（歷史流程評估）

| 角色           | 登入後第一入口 | 常用功能                         | 不應出現的操作                 |
| -------------- | -------------- | -------------------------------- | ------------------------------ |
| 負責人／管理員 | 今日營運摘要   | 班級、帳號、權限、分析           | 無權資料不應存在               |
| 教師           | 今日工作台     | 點名、進度、成績、被指派班級     | 新增班級、換教師、結業／封存   |
| 助教           | 今日工作台     | 點名與被授權的資料登錄           | 權限、帳號與生命週期操作       |
| 檢視者         | 學生／分析查詢 | 唯讀檢視                         | 所有新增、編輯、刪除與狀態變更 |
| 家長（未完成） | 孩子首頁       | 自己孩子的出勤、進度、成績與評語 | 其他學生、班級管理與內部備註   |

## 5. 流程合理性評估

| 項目                   | 現況                     | 評估   | 建議                                 |
| ---------------------- | ------------------------ | ------ | ------------------------------------ |
| 教材 → 班級 → 學生綁定 | 已建立正規化關係         | 合理   | 維持現有資料邊界                     |
| 班級 → 篩選學生名單    | 使用 `classId` URL       | 合理   | 返回學生詳情時保留 URL 情境          |
| 排課 → 今日點名        | 已由排課自動產生名單     | 合理   | 預設日期改為使用者所在地今天         |
| 點名 → 進度／成績      | 分散在不同頁             | 不順   | 建立今日工作台或班級日誌頁           |
| 學生進度 → 個人頁      | 缺少一致的深入查看入口   | 可改善 | 表格姓名與異常狀態直接連到個人頁     |
| 分析 → 原始資料        | 指標主要是彙總呈現       | 可改善 | 指標可下鑽至學生或班級篩選結果       |
| 成功／錯誤回饋         | 各功能方式不完全一致     | 可改善 | 統一成功訊息、欄位錯誤與衝突回復     |
| 行動版高頻操作         | 可使用，但表格操作較密集 | 可改善 | 點名與進度改成卡片／逐生快速操作模式 |
| 家長端                 | 尚未完成                 | 缺口   | 與內部管理介面分開導覽和資料權限     |

## 6. 建議調整優先序

### P0：串接資料庫前先確定

1. 將「今日工作台」定為老師的主要日常入口。
2. 定義一次課堂紀錄要保存哪些欄位：出勤、教材項目、頁數、考卷、得分、評語。
3. 決定一位學生同日多個班級或時段時，紀錄歸屬哪個 class/session。
4. 統一日期使用補習班所在地 local date，不在程式寫死展示日期。

這些會影響資料表與 JOIN，應在 Supabase migration 前完成。

### P1：提升老師日常效率

1. 新增今日工作台。
2. 點名後直接展開同一學生的今日進度／成績欄位。
3. 支援預設全體出席，再只修改例外。
4. 支援上一位／下一位學生與鍵盤操作。
5. 從學生詳情返回時保留班級與搜尋情境。

### P2：提升管理與追蹤

1. Dashboard 增加待處理工作：缺席未聯絡、落後學生、待批改成績。
2. 分析圖表支援下鑽到班級或學生名單。
3. 結業／封存加入原因與操作稽核紀錄。
4. 完成獨立家長端首頁與 RLS。

## 7. 目前建議先不要做的事

- 不需要新增更多彼此獨立的 Dashboard 頁面；應先整合日常工作入口。
- 不要讓老師從總學生名單逐一找人後才輸入每天紀錄。
- 不要在正式資料庫把班級、科目、學生或排課塞入單一 JSON 欄位。
- 不要讓前端自行判斷資料權限；仍須維持 Action → Service → Repository → RLS。

## 班級今日課堂進度

1. 進入「課程班級」，在上課中的班級選擇「今日課堂」。
2. 確認日期、時段與當次班級成員；系統依每位學生自己的啟用中學習計畫列出教材，不使用班級共同版本。
3. 出席或遲到學生預設帶入目前學習中、否則下一個尚未開始的項目；請假或缺席預設「本次不更新」。
4. 選擇學習項目與更新後狀態：尚未開始、學習中或已完成。
5. 備註可留空；若要記錄頁數，可輸入「看到 p.42」等自由文字，系統不解析或計算頁數。
6. 同一學生若當天使用多份教材，選擇「新增一筆教材進度」。
7. 所有學生資料調整完成後，確認受影響學生與筆數，再按「統一更新課堂進度」；任何一筆資料失效時整批不寫入。
8. 課堂完成後若漏登學生進度，可選擇「補登一筆教材進度」，完成多筆新增後填寫一次補登原因，再統一更新。
9. 已存在但內容錯誤的歷史紀錄仍使用逐筆更正，系統新增替代紀錄並保留原紀錄供追溯。

學生個人頁的「課堂紀錄」會合併顯示這些日期紀錄；教材版本仍只能從學生的「學習計畫」設定。
## 登入與帳號安全

1. 系統沒有公開註冊；Owner 到「帳號管理」建立教職員登入信箱、初始密碼、角色、班級範圍與啟用狀態。
2. 使用者從 `/login` 輸入信箱與密碼。錯誤帳密與停用帳號只顯示安全訊息，不會進入受保護頁面。
3. 使用者可按「忘記密碼」申請 Email 連結；畫面不會透露信箱是否存在。
4. 登入後點左側底部姓名進入「個人資料」，可寄送自己的修改密碼連結。
5. Email 連結限時且只能使用一次；更新密碼後，其他既有登入階段會失效。
6. Owner 可在「帳號管理」更新登入信箱、重寄設定、強制重設、撤銷登入、停用或恢復帳號；系統永遠不顯示既有密碼。
7. Owner 可從左側「操作紀錄」依日期、操作者、動作、資源與結果查詢；老師沒有此頁權限。

### Mock 與正式環境的差異

- 黃色「Mock 開發模式」存在時，只能使用假帳號與假資料，不可輸入真實學生個資或正式密碼。
- 正式環境不顯示身分切換器或測試帳密；Supabase／Email 尚未設定時，登入按鈕會安全停用。
- 正式上線前需由系統持有人提供 Supabase URL／keys、SMTP sender 與核准 Redirect URLs，詳見 [Supabase Auth、Email 與 Audit 正式串接交接](supabase-auth-audit-handoff.md)。
